Blind Instrument Audit

We ran three questionnaires the platform had never seen — two Federal Reserve household surveys and the CDC's national health interview script — straight through the pipeline, with every language-model call disabled. Fifteen defects surfaced on the first two. All fifteen are fixed; the third instrument found the wall we have not climbed yet.

02 · Defects

Fifteen ways a foreign document broke us

None of these were visible on our own client documents, because each client writes to one house convention and our parsers had quietly learned that one house. A federal instrument writes differently — and every difference was a silent failure, not an error message.

BRFSS is laid out as a table, and that defeats us. Every question is a row across five narrow columns — number, wording, variable name, responses, skip note. The PDF reader returns 8,103 fragments (“Thank you”, “very much,”, “but I seem to”) because each cell wraps every two or three words. PyMuPDF's own table finder reads some pages cleanly and returns noise on others, so building on it would produce results that vary page to page. This needs a real layout engine, not another rule.

04 · Routing

The base is written down. Now we read it.

Prose questionnaires state who gets asked each question in the margin — [IF S2 = 2 or S2=3], [ONLY ASK H0 – H6 IF S2 = 1], [IF (D1 = 3, 4, 5, OR 6)]. We were keeping those as decorative strings. They are now compiled into real conditions, which means the two checks that depend on them have something to check for the first time on a prose document.

The parser refuses more than it accepts, on purpose. A AND B OR C has no agreed precedence in a questionnaire margin, so it returns nothing and the directive stays as prose for a human. A guessed base is worse than no base: it silently reclassifies real respondents as routing violations, and nobody looks twice at a number the system produced confidently.

05 · Codes

Same answers, different numbers

Reading the base was only half of it. A file that ships answer text — Employed now rather than 1 — has no codes of its own, so the importer invents them alphabetically. The questionnaire's codes are the real ones: the screen-outs, the routing and the tab plan are all written against them. The two described the same answers under different numbers, and every code-level check was quietly comparing apples to oranges. Qualtrics exports choice text by default, so this is the ordinary case.

The option labels already matched exactly. So the fix is to join on them and renumber the data to the questionnaire — the data map and the data file together, or neither.

Only codes we invented are ever touched. SPSS files and Excel workbooks with a data map sheet carry the script's own codes, and those are left exactly as they are. The label travels with the value throughout, so nothing is reinterpreted — only the arbitrary integer identity moves. The join refuses on an ambiguous match, refuses on fewer than two matching labels, and is a no-op the second time it runs.

08 · Standing

Where we actually are

Proven

Format-agnostic on prose

Two PDFs from an institution with no relationship to us parsed to 104 and 125 questions, 93% and 97% of which appear as columns in the real data files. The handful that don't are grid parents and columns the Fed suppressed for privacy.

Proven

The cheap path is the main path

83 of 104 questions resolved with no model call at all. The 21 that didn't are numeric open-ends — "how many children aged 0–1", "what is your monthly rent" — where nothing in the text states the type.

Proven

Label-encoded files now compare

207 values across 52 columns renumbered to the questionnaire by matching option labels, so a Qualtrics-style choice-text export is checkable on the same terms as a coded one. Routing checks failing went 18 to 4, and the four that remain are our own mis-typed questions, not the alignment.

Limitation

Variable roles are Decipher-shaped

We recognise a punch column by a r1-style suffix. SHED writes R1_a, so all 323 columns were classified as questions, no hidden or system variables were identified, and the straightlining check found no grids to measure.

Limitation

Table-laid-out PDFs are out of reach

BRFSS is not an outlier — CATI scripts and many agency programming documents are authored as grids. Reading them needs page-layout analysis (PyMuPDF suggests its own pymupdf_layout), which is a project, not a patch. Until then, a document like this should be rejected at upload with a clear reason rather than half-parsed.

Open

Linking stops at 76 of 104

Grid parents (T0, T1, A1, C4) own a family of columns rather than one, and the linker wants a single name. Every unlinked question is a question the QC cannot check.

Proven

The gate is a gate again

Two orchestration tests were making live model calls, so the suite's runtime tracked a third party's uptime — 45 seconds each on a good day, twenty minutes stuck in a socket read on a bad one. The suite now refuses the network outright and runs in 46 seconds. Those two tests dropped to 0.2 s without changing what they assert.

Proven

A checker that admits what it did not read

When extraction cannot resolve a field, the cross-check now skips the checks that would assert on it rather than judging the data against a default we picked. An unknown type used to fall back to "single answer" and then report every multi-select respondent as a violation.

09 · Assumptions

What this test does and does not prove

  • Two instruments from one institution is still one house style. SHED 2013 and 2014 are long, well-scripted, English-language prose questionnaires from the same authors. Together they are a fair stand-in for a client screener — not for a conjoint exercise, a MaxDiff block, or a translated tracker.
  • "104 of ~104" is a count, not a grade. We counted labelled questions; we did not hand-verify the wording, options and base of all 104 against the PDF. The 93% column-match rate is the independent check, and it is a strong one.
  • Zero model calls is the floor, not the norm. Backends were disabled to make the deterministic result measurable. In production the 21 unresolved questions would each cost a call — roughly 41 attempts with retries.
  • Timings are laptop timings on a warm filesystem, single-threaded, no network, no database. The server adds upload, storage and queue time on top.
  • Findings were reviewed, not adjudicated. "Refused is the extra punch" is a reading of the pattern across 34 findings, not a claim verified case by case.
