DVV Research Cloud

DVV Research Cloud · Briefing, September 2026

A questionnaire, fielded the same day it lands.

The document does the scripting. A researcher checks the result. Nothing reaches a respondent until four separate checks agree it should.

The problem

Scripting is the bottleneck in every project

A client sends a Word questionnaire. Somebody reads all forty pages and rebuilds it by hand in a survey tool — every question type, every answer list, every "ask only if", every screen-out, mask and pipe.

It takes days. It is the step that decides whether the project starts this week or next. And it is where the expensive mistakes live: a base pointing at the wrong question, a screen-out that fires on everyone, a brand list that shows brands the person never heard of. Those are found in field, after real money has been spent on real respondents.

How it works today

  • Days of scripter time per study
  • Capacity capped by how many scripters you have
  • Errors found by a human re-reading, or by a respondent
  • The same house conventions re-learned by each new scripter
  • Data map arrives after scripting, not before

With this system

  • The document is read automatically; a researcher reviews it
  • Capacity is a review queue, not a build queue
  • Four checks stand between a mistake and a respondent
  • Conventions are taught once and applied to every future document
  • Data map is fixed at approval — before anyone is let in

What it does

Six things, end to end

01

Reads the questionnaire

Word or PDF in. Questions, types, answer lists with their punch codes, bases, screen-outs, grids, ranking, constant sums, loops and hidden variables out — with a note beside each one saying which line of the document it came from.

02

Puts a researcher in charge of the result

A review screen that groups questions the way a researcher thinks — screener, profile, core, loops, open-ends, hidden — shows which questions depend on which, and lists every unresolved issue as something clickable rather than a warning to ignore.

03

Learns your house style

When a reviewer corrects a misread, they can teach the convention instead of just fixing the question: "in this client's documents, this phrase means a multi-select". Re-read applies it across the whole questionnaire, and every document that client sends afterwards.

04

Fields the survey

A live link, one question per screen, built for a phone. Screen-outs, quotas, masks and pipes are all decided on our server — never in the respondent's browser. Soft launch holds at a set number of completes so the first data can be checked before full field.

05

Watches the field

Starts, incidence, where people screen out and on which rule, where they drop off, median interview length, and now what device they answered on and whether their stated location agrees with their connection — flagged, never acted on automatically.

06

Delivers

A clean data file and data map, cross-tabs, a deck, and a read-only link for the client. Plus an assistant that answers questions about the project — including what respondents typed in the open-ends, searched by meaning rather than keyword.

Why this, and not something off the shelf

Four decisions that are hard to copy

It reads rules, not vibes

Roughly two thirds of a questionnaire is understood by parsers that know market-research conventions — no AI involved, same answer every time, and a line of the document to point at. AI is used only for what is genuinely left over.

It gets better with each client

Every correction can become a taught convention. The system that reads your second study for a client is measurably better than the one that read the first — and it is your team's knowledge, not a vendor's.

Mistakes stop before respondents

Review flags, a dry run through every rule, a server-side pre-link check that can refuse to create the link, and a soft-launch hold. Four independent gates, each catching what the others miss.

The data stays where it belongs

One private stack per client. Open-weight models only — no OpenAI or Anthropic anywhere in the code. Respondent locations are resolved from a file on the server; no address is ever sent to an outside service.

The promise is not "AI reads your questionnaire". It is that a mistake does not reach a respondent.

What a client receives

The handover

  • A live survey link that works on a phone, with the routing their document described.
  • A data map — every column, every label, every missing-value code — available at approval, before field.
  • A data file in SPSS or Excel, one column per answer, punch codes intact.
  • Field reporting: incidence, screen-out reasons, drop-off, interview length, device split.
  • Tables and a deck, plus a read-only share link for their own stakeholders.

What is next

The next three moves

Immediate

Turn on meaning-based search in production

The embedding model is a one-line change to the server configuration. Until it is on, the assistant searches questions and open-ends by wording only — and says so in every answer.

Next

Run one client bundle end to end

A private stack, a licence key, a real questionnaire, a real field, a real delivery — start to finish, on infrastructure that is not a developer's laptop. Nothing is genuinely proven until this has happened once.

After that

Widen the reading, on real documents

Every questionnaire from a new client is a test of the parsers. The benchmark set has already surfaced parser defects that no amount of internal testing would have found — that loop continues, and each fix is permanent.

Decisions we need

What we are asking for

Three things, in order

  1. One real questionnaire to run end to end. Not a demo document — a live project with a deadline, so the gaps show up where we can fix them.
  2. A decision on hosting. One stack per client on our infrastructure, or in the client's own cloud. Both are built; the choice changes what we quote and what we promise on data residency.
  3. Who reviews. The system replaces scripting, not judgement. Somebody has to own the approval step — the person who says "yes, this is what the client asked for" before the link goes out.
